# 씬 조립 · 재질 · 배치

씬은 `CSGScene.Kind` 로 고르고, 앱은 **시작 메뉴에서 `Kind.allCases` 를 그대로 그린다** —
`Kind` 에 case 를 추가하고 `title`/`subtitle`/`symbol` 만 채우면 **버튼이 자동으로 생긴다.**
메뉴 화면(`ContentView`)은 건드릴 필요가 없다.

**기존 씬을 지우지 말고 Kind 를 추가**한다 — 이 저장소는 git 이 아니라 되돌릴 수 없다.
같은 형상을 다른 재질로 보여 주는 변형은 빌더에 인자를 하나 넣는 쪽이 싸다
(`buildBus(glass:)` 가 `.bus` 와 `.glassBus` 를 함께 만든다).
스냅샷은 `make snapshot SCENE=<이름>` 으로 코드 수정 없이 씬을 고른다.

각 `build*()` 는 세 단계로 되어 있다:

1. **재질 등록** — `addMaterial(color, type:, ior:)` 가 인덱스를 돌려준다
2. **오브젝트 조립** — CSG 식으로 만들고 `objects` 배열에 넣는다
3. **배치** — `placements` 에 `Placement(objectIndex:transform:)`. 같은 오브젝트를 여러 번 배치해도 가속 구조는 하나만 쓴다

`objects` 배열 순서 = `objectIndex`. **중간에 오브젝트를 끼워 넣으면 뒤쪽 인덱스가 전부 밀린다** —
배열 끝에 추가하고 `placements` 에 한 줄 붙이는 쪽이 안전하다.

## 변환 규칙

`.translate(x,y,z) * .rotateY(deg) * .scale(s)` — **오른쪽부터** 적용된다 (스케일 → 회전 → 이동).
조립체 전체를 옮기려면 `.transformed(m)` (모든 부품 행렬에 앞에서 곱한다).
회전각은 라디안이 아니라 **도(degree)** 다.

## 재질

| type | 동작 | 주의 |
|---|---|---|
| `MATERIAL_DIFFUSE` | 확산 + 반구 앰비언트 + 클리어코트 하이라이트 + 프레넬 환경 반사 | `gloss` 로 광택 조절 |
| `MATERIAL_METAL` | 완전 거울, `color` 로 착색 | `MAX_BOUNCES`(6) 회 반복. 거울끼리 마주 보게 두면 급격히 느려진다 |
| `MATERIAL_GLASS` | 스넬 굴절 + Schlick 프레넬 + 전반사, `ior` 사용 | 반사 가지는 1회 추적 근사 |

`addMaterial(_:type:ior:gloss:grain:)` 의 뒤 두 인자가 사실감을 좌우한다:

- **`gloss`** (0~1): 하이라이트 세기 + 프레넬 환경 반사량. 도장 0.9, 고무 0.2~0.35, 노면 0.08.
  **0 이면 아무리 형상이 정확해도 점토 모형처럼 보인다.**
- **`grain`** (0~1): 절차적 얼룩. 완벽하게 균일한 큰 면(특히 노면)은 조명이 아무리 좋아도 CG 티가 난다.

**색 있는 유리를 만들 때**: 어두운 색을 그대로 `MATERIAL_GLASS` 에 쓰면 거의 검게 막힌다 —
유리를 통과할 때마다 `color` 가 곱해지므로 0.04 짜리 색은 두 번만 지나도 0 에 가깝다.
색을 흰색 쪽으로 끌어올려야(`lift`) 색은 남고 투과가 산다. `buildBus(finish: .tinted)` 가 그 예다.
온통 유리인 씬은 `MAX_BOUNCES`(6)를 금방 소진하는데, `rtKernel` 이 **남은 에너지를 하늘로 근사**하므로
예전처럼 까맣게 죽지 않는다.

유리는 **닫힌 솔리드**여야 제대로 보인다. 열린 껍데기(`sphere - sphere - box` 같은 종 모양)는
구간이 실제 두께를 반영하므로 괜찮지만, 두께 0 인 판을 유리로 두면 굴절이 무의미하다.

부품마다 재질을 따로 줄 수 있고, 차집합의 절단면은 **자르는 쪽 부품의 재질**을 물려받는다.
알약(`capsulePill`)이 이 성질을 이용해 반씩 다른 색을 낸다.

## 자주 나는 문제

**형상이 잘려 보인다 / 가장자리가 사라진다**
오브젝트 AABB(`CSG.bounds()`)가 실제보다 작다. `PartKind.extent` 가 그 부품의 로컬 반폭과 맞는지 확인한다.
AABB 는 커도 결과는 맞고 성능만 손해이므로, 의심되면 일단 키운다.

**구멍이 안 뚫린다 / 형상이 뭉개진다**
`ShaderTypes.h` 의 `CSG_MAX_INTERVALS`(6) 초과. 레이 하나가 오브젝트를 통과하며 만드는 구간 수 한계다.
구멍이 많거나 서로 떨어진 부품을 여럿 합친 물체가 여기에 걸린다
(예: `gems` 처럼 4개를 나란히 두면 축 방향 레이가 구간 4개를 만든다).

**"CSG 스택 깊이 초과" 에러가 뜬다**
`Renderer` 가 오브젝트마다 `CSG.stackDepth()` 로 미리 검사한다 — 조용히 부품이 사라지는 대신 에러가 난다.
후위 표기 스택 머신이라 **왼쪽으로 치우친 체인이 깊이 2로 최소**이고, 균형 트리는 log₂(n)+1 로 커진다.
`CSG.unionAll` 이 왼쪽 체인으로 묶으므로 **부품이 여러 개면 `unionAll([...])` 을 쓴다.**
`a - (b - (c - d))` 처럼 **오른쪽으로 중첩**시키면 깊이가 그대로 늘어난다.
현재 씬의 최대 깊이는 3, 한계는 5다.

**한계값을 올릴 때 (`ShaderTypes.h`)**
`CSG_MAX_INTERVALS` 와 `CSG_MAX_STACK` 은 intersection function 의 **스레드 스택 사용량**을 지배한다:
`IntervalList` = 36B × `CSG_MAX_INTERVALS` + 4 = 220B, `evalCSG` 의 `stack[CSG_MAX_STACK]` 이 그 대부분.
너무 키우면 A15 같은 기기에서 파이프라인 생성이
`Compute pipeline exceeds available stack space` 로 실패한다 (M2 Pro 는 통과하므로 **macOS 에서는 안 잡힌다**).
올렸으면 반드시 실기기에서 확인할 것.

**차체에 붙인 몰딩·램프가 앞뒤에서 밖으로 떠 있다**
평면도가 둥근 물체(`roundedRectPrism`)에 **직선 상자를 붙이면 코너에서 삐져나온다.**
띠(벨트라인·범퍼·도색)는 같은 평면도를 `out` 만큼 키운 `roundedRectPrism` 으로 만들고,
앞뒤 끝에 붙이는 램프·간판은 그 x 에서의 실제 반폭 안에 넣는다 (`Bus.halfWidth(atX:)`).

**창이 새까맣다 / 유리가 구멍처럼 보인다**
두 가지가 흔하다.
1. **테두리를 속 찬 상자로 만들었다.** 창틀·문틀은 `상자 − 안쪽 상자` 로 가운데를 뚫어야 한다.
   그냥 상자로 두면 유리를 통째로 덮어 버리고, 검은 재질이면 구멍처럼 보인다
   (`Bus.windowFrames` 의 `frame(_:_:_:)` 이 이걸 한다).
2. **실내를 파낸 재질이 검다.** 차집합의 절단면은 자르는 쪽 재질을 물려받으므로
   그게 곧 실내 벽 색이다. 검게 두면 유리 너머가 새까매서 유리로 안 보인다 (`Bus.Materials.cabin`).

**부품 표면에 흑백 얼룩(스티칭)이 생긴다**
겹쳐 놓은 두 부품의 **바깥면이 정확히 같은 평면**이면, 픽셀마다 어느 쪽이 이기는지 갈려 얼룩이 된다
(램프 렌즈와 그 뒤 검은 베젤에서 실제로 겪었다). 앞면 x 를 **최소 2~3 cm 어긋나게** 둔다.
광택 있는 평면이 노이즈(`grain`) 있는 바닥을 비출 때도 비슷한 반짝임이 생기므로,
`valueNoise` 의 최고 주파수를 화면 픽셀보다 촘촘하게 올리지 않는다.

**부품이 통째로 사라진다 / 파묻힌다**
`roundedPanel` 은 **z 방향 압출**이다. 차량 앞뒤 면에 붙일 판은 `.rotateY(90)` 을 곱해
x 방향으로 눕혀야 한다. 빼먹으면 판이 차체 속으로 길게 누워 화면에서 사라진다 (LED 행선판에서 겪었다).
반대로 **이미 눕힌 것에 또 회전을 곱하면** 얇은 판이 깊은 슬롯이 된다 (앞유리에서 겪었다).
`Bus` 는 앞이 **-x** 이므로 "더 앞" = x 가 더 작은 쪽이다 — 가림 순서를 이걸로 따진다.

**앞뒤에 붙인 부품이 안 보인다**
범퍼 같은 띠가 그 부품보다 바깥(앞)에 있으면 가려진다. 번호판·안개등은
범퍼 띠의 바깥 반지름(`L + out`)보다 **더 앞**에 놓아야 한다.

**차 안에 넣은 것이 휠 아치 구멍으로 비친다**
휠 아치는 차체를 원기둥으로 파낸 것이라, 실내 오브젝트가 그 영역
(x = 축 ± 아치반지름, y ≤ 축높이 + 아치반지름)에 겹치면 구멍 너머로 그대로 보인다.
`Bus.interior` 는 뒷바퀴 위 좌석을 아치 윗선보다 높이 올려 이걸 피한다 — 실차도 그렇게 생겼다.

**모서리를 둥글리고 싶다**
덩어리에는 **`CSG.roundBox(half:radius:)`** 를 쓴다 — 진짜 둥근 상자(상자 ⊕ 구), 부품 1개.
윤곽 교차(`roundedRectPrism` ∩ `roundedPanel` ∩ `roundedSection`)로 흉내 내면
모서리는 둥글어져도 **꼭짓점에 대각선 능선이 남는다.**
한 방향만 둥글리고 싶을 때만 윤곽을 쓴다.

자세한 것(왜 능선이 생기는지, 한쪽만 둥글리는 법, 새 매끄러운 부품 추가)은 **`smooth-surfaces` 스킬**.
`roundedPanel` 은 창·문 구멍, 램프, 표지판처럼 "정면에서 봤을 때 모서리가 둥근 것" 에 그대로 쓴다 —
각진 상자와 비용이 같으므로 창 구멍을 각지게 둘 이유가 없다.
방향을 바꾸려면 `.rotateY(90)`(x↔z) / `.rotateX(90)`(y↔z) 을 곱한다.
**이미 z 로 압출된 것에 또 회전을 곱하면 얇은 판이 깊은 슬롯이 된다** — 앞유리에서 실제로 겪었다.

**형상은 맞는데 "실물 같지 않다"**
셰이딩과 환경 문제일 가능성이 크다. 순서대로 확인한다:

1. **`gloss` 가 0 인가.** 확산만 있으면 하이라이트도 환경 반사도 없어 점토가 된다.
2. **큰 면이 완전한 평면인가.** 평면은 법선이 일정해서 빛이 전혀 흐르지 않는다.
   `Bus.body` 는 반경 22 m 짜리 대반경 원기둥 두 개로 옆면을 4 cm 볼록하게 만든다 —
   실루엣은 그대로면서 지평선 반사가 띠처럼 지나간다.
3. **반사할 것이 환경에 있는가.** 빈 하늘만 있으면 광택을 줘도 단색이다.
   `.bus` 씬이 차선 · 연석 · 건물 블록을 두는 이유가 이것이다 (형태는 상자로 충분하다).
4. **큰 면에 `grain` 이 없는가.** 균일한 노면은 즉시 CG 로 보인다.
5. **톤 매핑.** 단순한 `x/(1+x)` 는 1 이하 값까지 압축해 화면을 통째로 회색으로 만든다.
   화이트포인트를 넣은 확장 Reinhard 를 쓴다 (`rtKernel` 끝).

**실물과 비교해서 고칠 때**
사진을 말로 기억하지 말고 **실제로 받아서 본다.** Wikimedia Commons 는 자유 라이선스라 안전하다:

```bash
# 1) 파일명 찾기 → 2) API 로 원본 URL → 3) curl → 4) sips 로 줄여서 Read
curl -s -G "https://commons.wikimedia.org/w/api.php" --data-urlencode "action=query" \
  --data-urlencode "format=json" --data-urlencode "prop=imageinfo" \
  --data-urlencode "iiprop=url|extmetadata" --data-urlencode "titles=File:..."
curl -sL -A "Mozilla/5.0 ..." -o ref.jpg "https://upload.wikimedia.org/wikipedia/commons/<a>/<ab>/<name>"
sips -Z 1200 ref.jpg --out ref.png     # Read 로 열어 실제로 확인
```

`thumb.wikimedia.org` 썸네일 URL 은 에러 HTML 을 돌려준다 — **원본 경로**(`upload.wikimedia.org/wikipedia/commons/<a>/<ab>/`)를 쓰고
User-Agent 를 붙일 것. 받은 뒤에는 치수 비율(전고 대비 창 띠 위치 등)을 실제로 재서 맞춘다.

**모델이 장난감처럼 보인다**
십중팔구 비율이다. **로컬 좌표를 미터로 두고 실차 치수를 넣는다.**
버스가 그랬다 — 길이 대 폭이 2.7:1(장난감)에서 4.4:1(실차)로 가면서 완전히 달라졌다.
바퀴 지름 / 전고 비도 큰데, 0.6 이면 몬스터트럭이고 실차는 0.35 언저리다.

**둥근 껍데기에 구멍이 뚫린다 / 검은 판이 차체 밖에 서 있다**
둥근 껍데기 안에 **각진 상자**를 넣거나 각진 상자로 속을 파내면, 코너가 말려 들어간 만큼
상자가 뚫고 나온다. 이 저장소에서 지붕 슬롯 · 뒤 코너 관통 · 엔진실 돌출로 **세 번** 났다.
파내는 것도 같은 둥근 상자로 만들고(반지름만 `r - 벽두께`), 넣는 물체는 그 지점의 실제 반폭에서
역산한다 (`Bus.cabinHalfWidth(atX:y:)`). 자세한 것은 **`smooth-surfaces` 스킬**.
**곡면을 쓴 오브젝트는 위·아래·뒤에서도 스냅샷을 찍어 확인할 것** — 정면에서는 안 보인다.

**층이 있는 기계를 만들 때**
맞물리는 기어를 **같은 높이에 두면 뒤 기어가 앞 기어를 통째로 파고들어 한 덩어리로 뭉친다.**
중심거리를 맞춰도 소용없다 — 뒤 기어 **자신의** 반지름이 그보다 크기 때문이다.
실물처럼 **층을 쌓고 피니언만 아래층으로 내려보낸다** (`Watch.wheelY(i)`).
덮개(브리지)도 하나의 높이로 통일하면 낮은 부품 위에 붕 뜬다 — 각자 덮는 것 바로 위에 앉힌다.
**작은 부품이 두께 속에 파묻히지 않게** 윗면 높이를 계산해서 앉힌다 (`Watch.bridgeTopY`).

**오브젝트 인덱스는 배열 순서와 정확히 맞춘다**
`objects` 배열에 하나를 끼워 넣으면 그 뒤 인덱스가 전부 밀린다.
실제로 케이스 링이 샤통 자리마다 깔려 화면이 거대한 띠로 뒤덮인 적이 있다.
인덱스를 상수로 뽑아 두고, 배열을 고칠 때 같이 고친다.

**부품이 수백 개인 모델을 만들 때**
비용은 부품 수가 아니라 **오브젝트 수와 재질(금속·유리 바운스)** 이 지배한다.
`Watch` 는 부품 606개인데 오브젝트 20개 · 인스턴스 483개로 묶어 버스와 비슷한 속도가 나온다:

- **반복되는 것은 전부 인스턴스** — 보석·나사·페를라주는 오브젝트 1개 + 배치 N개
- **반복 요소가 한 줄로 늘어서면 오브젝트를 나눈다** — 기어 하나 = 오브젝트 하나
  (톱니를 한 덩어리로 묶으면 평면 방향 레이가 구간 한계를 넘는다)
- 겹쳐 찍는 장식(페를라주)은 **높이를 조금씩 흔들어야** 윗면이 같은 평면이 안 되어 얼룩이 없다

**축 둘레로 반복되는 물체 (제트엔진 · 팬 · 터빈)**
`RayTracer/Engine.swift` 가 표준이다. 규칙 하나: **한 단(stage)을 통째로 오브젝트 하나로 만들지 않는다.**
날개 40장을 한 덩어리로 합치면 원주 방향 레이가 그 자리에서 `CSG_MAX_INTERVALS` 를 넘긴다.
**날개 한 장 = 오브젝트 하나, 날개 수만큼 `rotateX` 인스턴스**로 두면 오브젝트 40여 개에
인스턴스 1500개가 되고 가속 구조는 오브젝트 수만큼만 선다 (1600×1000 렌더가 0.6초).

비틀린 날개는 짧은 `roundBox` 를 반경 방향으로 쌓아 만들되 **조각을 제 길이만큼 겹친다** —
겹치면 합집합이 구간 하나로 합쳐지므로 **조각을 늘려도 구간은 안 늘어난다.**
매끄러움은 조각 수로 사고 값은 겹침으로 치른다.

**비틀림 각은 축에서 잰다**: 루트는 원주속도가 느려 유동이 거의 축 방향이라 작은 각,
팁은 회전면에 가깝게 누워 큰 각. 반대로 넣으면 정면에서 날개가 실처럼 보인다.

**큰 물체는 오브젝트를 쪼갠다**
구간 한계는 오브젝트 단위다. 버스처럼 창틀 기둥 · 좌석 · 범퍼 · 바퀴가 한 줄로 늘어선 물체를
한 덩어리로 만들면 길이 방향 레이가 6구간을 쉽게 넘어 뒤쪽이 조용히 사라진다.
`Bus` 는 차체 · 유리 · 실내 · 부속 · 바퀴 다섯으로 나누고 같은 `busXform` 으로 겹쳐 배치한다
(`RayTracer/Bus.swift`). 반복되는 부품은 오브젝트 하나 + 인스턴스 여러 개로 두면 가속 구조도 아낀다.

**화면 전체가 소금후추처럼 지글거린다 (형상은 멀쩡한데 픽셀마다 얼룩)**
**같은 평면에 놓인 경계면**이 원인이다. 형상이 깨지는 게 아니라 픽셀마다 부동소수점 오차의
방향이 갈려서 맞았다 안 맞았다 하는 것이므로, "가장자리가 이상하다"가 아니라 "화면이 지글거린다"로 나타난다.

| 어디서 | 왜 |
|---|---|
| `A - B` 에서 A 와 B 의 **끝 캡이 같은 평면** | 오차만큼의 머리카락 같은 판이 남는다. 껍데기(바깥−안쪽)를 만들 때 안쪽 윤곽을 양 끝에서 조금 **더 길게** 뽑아야 한다 |
| `lathe` 처럼 조각을 **딱 붙여** 쌓은 합집합 | 조각 사이에 오차만큼의 틈이 생기고, 축 방향 레이가 **틈마다 구간을 하나씩** 만들어 `CSG_MAX_INTERVALS`(6)를 넘긴다. `CSG.lathe` 는 이제 조각을 제 기울기대로 늘려 겹치게 한다 |
| 겹쳐 놓은 두 부품의 **바깥면이 같은 평면** | 어느 쪽이 이기는지 픽셀마다 갈린다. 2~3 cm 어긋나게 둔다 |

**원인을 좁히는 법**: `placements` 를 오브젝트 하나씩만 남기고 렌더한다.
얼룩을 만드는 오브젝트를 빼면 **그 뒤에 있던 것까지 함께 깨끗해진다** — 앞쪽 오브젝트의
가짜 교차가 뒤쪽을 덮어 칠하기 때문이다. 그러니 "얼룩이 낀 부품"이 범인이 아니라
**그 앞에 있는 부품**이 범인일 수 있다. 터보팬에서 블레이드가 지글거렸는데 범인은 나셀이었다.

**차집합의 절단면 색**
`A - B` 의 잘린 면은 **자르는 쪽(B)의 재질**을 쓴다. 커터웨이 단면을 붉게 칠하는 것,
껍데기 안쪽 벽을 바깥과 다른 색으로 두는 것이 전부 여기서 공짜로 나온다 —
메시였다면 단면을 손으로 막아야 한다 (`Engine.shell(outer:inner:inside:)`).

**느리다**
- `MetalView(renderScale:)` — 기본 0.6. `ContentView.swift` 에서 넘긴다. 0.4 까지 내리면 체감이 크다
- `MAX_BOUNCES` 를 6 → 3 으로
- 거울/유리 오브젝트 수를 줄인다. `roundedBox` 는 부품 27개짜리라 특히 비싸다
- A13~A16 은 RT 전용 유닛이 없어 순회를 셰이더 코어로 처리한다. A17 Pro / M3 이상과 체감 차이가 크다

## 갑옷 · 로봇 (아이언맨 — `IronMan.swift`)

인물상 골격 위에 **`roundBox` 판**을 얹는다. 기계는 능선이 있어야 하므로 blob 은 언더슈트·흉갑처럼
몸을 따라 흐르는 큰 덩어리에만 쓴다.
- **팔·다리는 관절을 원점으로 −y 로 늘어뜨린 표준 자세**로 만들고 배치 변환으로 돌린다 — 그래야 판이 축 정렬 상자다
- **헬멧 페이스플레이트는 껍데기 앞에 붙이지 말 것.** 튀어나오고 껍데기가 뚫고 나와 잡음이 낀다.
  같은 껍데기를 마스크 영역으로 둘로 가른다: 붉은 = 껍데기 − 마스크, 금 = 마스크 ∩ 평면으로 깎은 다면체 (0.03 앞으로)
- 금·강철은 **`MATERIAL_SATIN`** (색으로 착색된 프레넬 반사 F0 ≈ 0.7·color + 확산 바탕 절반).
  `METAL` 은 어두운 스튜디오를 비춰 녹은 금덩이가 되고, `DIFFUSE` 는 겨자색 플라스틱이 된다
- 환경은 `.brightStudio` (중간 회색 배경 + 소프트박스 넷 + 카메라 쪽 필). 어두운 `.studio` 에선
  금속 반사가 회색으로 죽는다. `CSGScene.exposure` 로 노출도 씬마다 조정
- **패널 라인**: `inset()` 은 **판과 같은 색**으로 얕게(0.022) 파서 단차 그림자만 남긴다 —
  어두운 색으로 파면 창문처럼 보인다. 검은 선은 `groove()`(폭 0.035) 로만
- **볼트**: 오브젝트 하나(`bolt`)를 `(위치, 법선)` 목록 + 부위 배치 변환으로 인스턴싱 (`boltPlacements`)
- 어깨는 공이 아니라 기울인 판 두 장이 겹친 견갑
- 눈·아크 리액터·리펄서는 `MATERIAL_EMISSIVE` (color 3~6 이면 희게 타며 색 테두리가 남는다)
- 다리 판 폭은 다리 반지름 + 0.1 이하, 스탠스는 ±1.45 — 붙으면 두 다리가 한 덩어리로 보인다
- 언더슈트 목이 그대로 드러나면 마네킹 — 고짓(목 갑옷 고리)을 두른다

## 흰 타일 · 어두운 사각 얼룩이 화면에 남는다 (GPU 가 스레드그룹을 죽였다)

무거운 씬(유리 수백 개 × 바운스 6 × 4 spp × 베지에 blob)에서 **커맨드 버퍼 에러도 없이**
스레드그룹 단위로 흰(안 써진) 타일이나 25% 어두운 타일이 남는다. 워치독 "Impacting Interactivity"
에러가 찍히기도 하고 안 찍히기도 한다. 스레드 **하나**의 실행 시간이 문제라 띠로 나눠도 소용없다.
답은 스레드를 짧게 만드는 것 (`Renderer.encodeBanded`, 샹들리에에서 배웠다):
- 슈퍼샘플링은 커널 안 루프가 아니라 **패스** — 샘플마다 디스패치, 누적 버퍼에 더하고 마지막 패스가 평균
- 한 프레임을 **가로 띠(128행)** 의 커맨드 버퍼로 — 워치독 방어
- `CSGScene.maxBounces` — 유리가 수백 개면 4
- `CSG.blob(..., maxSteps:)` — 가는 튜브는 100, 전선은 80. 팔 blob 8개의 AABB 가 중앙에서 겹치면
  그 레이는 blob 을 8번 추적하므로 **스텝 수가 곧 스레드 길이**다. 셰이더 기본은 160
- **천장을 그리지 마라** — 키 라이트가 지향광이라 천장이 있으면 방 전체가 그림자에 잠긴다.
  전구 줄·풍선 높이로 천장을 암시한다 (`PartyRoom.swift`)
원인을 가르는 법: spp 1 로 / 의심되는 오브젝트만 빼고 렌더해 어느 쪽에서 사라지는지 본다.

## 자동차 (스포츠카 — `SportsCar.swift`)

**차체는 blob 이다.** 타원체 열 개(코·보닛·카울·도어·데크·꼬리·파워 벌지·펜더 넷)를 blend 2 안팎으로
섞은 덩어리를 **잘라 낸다**: 바닥 평면(∩ 상자), 휠 아치(− 원통), 콕핏(− 둥근 상자), 그릴 입(− 타원체),
헤드라이트 자리(− 구), 패널 라인(− 얇은 상자). 버스처럼 둥근 상자로 쌓으면 이 세대 차의 흐르는 곡면이 안 나온다.
- **차 밑을 막아라** — 아치가 관통이라 밑이 뚫려 있으면 반대편 바퀴가 아치 너머로 보인다.
  검은 섀시 판(문턱 안쪽에 숨겨서) + 아치보다 살짝 작은 검은 휠 하우스 라이너
- `rotateZ(90)` 을 원기둥에 걸면 **로컬 x 가 세계 y** 가 된다 — 스케일은 (높이, 두께, 폭) 순. 그릴 링이 세로 타원이 된 적이 있다
- 헤드라이트 보울은 튀어나온 구가 아니라 **파낸 반구**(구 − 앞쪽 구) 위에 유리 블리스터
- 와이어 휠: 타이어 토러스 + 크롬 림(원통 − 원통) + 허브 회전체가 오브젝트 하나, 스포크는 원기둥 하나를
  휠 로컬 좌표에서 두 줄 × 24개로 계산한 뒤 **휠 배치 변환 × 스포크 변환**으로 192번 인스턴싱
- **곡면 위에 얹는 소품(루버·와이퍼)은 blob 에 구멍을 파지 말고 별도 오브젝트로** — 보닛을 스치는 레이가 홈 여러 개를
  지나며 구간 한계를 넘긴다. 높이는 `SportsCar.surfaceY` 처럼 **같은 SDF 를 CPU 에서 이분법**으로 풀어 잰다.
  감으로 넣으면 곡면이라 반은 묻히고 반은 뜬다. 법선(`surfaceNormal`)으로 기울기까지 맞춘다
- **차의 사실감은 환경**이다: `brightStudioEnv` 의 수평 라이트 바(dir.y ≈ 0.36, 0.62)가 옆구리에 반사선을 흘린다.
  원형 소프트박스만으로는 반사가 점점이 흩어진다
- 소프트 섀도는 **첫 히트에서만** (`shadeSurface(…, shadowSoft:)`). 크롬·유리 바운스마다 8개씩 쏘면 스레드가 죽어
  검은 타일이 남는다

## 크리스털 · 유리 인스턴싱 (샹들리에 — `Chandelier.swift`)

- 깎은 크리스털 = `ngonPrism(8) ∩ 타원체` (양 끝이 뾰족한 팔각 프리즘). 볼록이라 구간 1개
- 비즈 체인 = 팔각 원반 하나를 늘어진 곡선(`p.y −= sag·4t(1−t)`)을 따라 인스턴싱
- 황동 팔은 베지에 튜브 blob 하나를 `rotateY` 로 8번. 팔 뿌리 마디·장식 컬도 같은 blob 안에
- 촛불은 `MATERIAL_EMISSIVE` (5.5/3.6/1.4). 어두운 `.studio` 여야 크리스털이 빛난다
- 큰 구슬은 구 ∩ 상자 6개 (60° 간격) — 면이 있어야 유리로 읽힌다

## 제품 사진 (안경 · 썬글라스 — `buildSpectacles` / `buildSquareSunglasses`)

사실감의 대부분은 형상이 아니라 **조명·배경·안티에일리어싱**에서 왔다. 씬 속성 세 개로 켠다:

| 속성 | 값 | 효과 |
|---|---|---|
| `environment = .whiteCyc` | 흰 사이클로라마 (`whiteCycEnv`) | 배경은 노출 과다 순백, 소프트박스가 금속·유리에 그라데이션으로 비친다. 지평선 **위는 전부 흰색**이어야 화면 위쪽에 회색 띠가 안 생긴다 |
| `shadowSoftness = 0.06` | 광원 각반지름(rad) | 그림자 레이 8개 → 부드러운 접지 그림자. 8배 비싸니 작은 씬만 |
| `samplesPerPixel = 4` | 2×2 슈퍼샘플링 | 철사 테·속눈썹처럼 픽셀보다 얇은 것의 계단 제거 |

흰 환경은 밝아서 **금속 색은 실제보다 어둡게** 둬야 금으로 보이고 (로즈골드 0.74/0.50/0.36),
검은 광택 재질은 회색으로 떠서 **더 검게, 광택은 낮춰야** 한다. 완전 투명 유리는 흰 배경에서
사라지므로 아주 옅은 회청색(0.92/0.94/0.96)을 준다.

**그라데이션 렌즈**: 띠로 나누면 열 개여도 계단이 보인다. `MATERIAL_GLASS` 에서 `grain` 이 세기,
`gloss`/`sss` 가 맑아지는 아래 y / 짙은 위 y 인 **높이 착색**을 쓴다 (셰이더 유리 분기).
렌즈에는 **베이스 커브**(구면 껍데기와 교집합)를 줘야 하이라이트가 렌즈를 가로질러 흐른다.
힌지 같은 각진 작은 부품은 blob 안에 넣지 말고 `roundBox` 부품으로 — blob 안에서는 이웃과 섞여 공이 된다.

## 카메라

앱에서는 **수동 궤도 카메라**다 (`Renderer.Camera` — 방위각 · 고도각 · 줌).
드래그/핀치가 `orbit(dx:dy:)` · `zoom(by:)` 를 부르고, 스냅샷은 `T` 로 방위각을 직접 준다.
FOV 50°, 고도 기본 약 18°. **거리는 씬이 정한다** —
`CSGScene` 의 `focusCenter` · `focusRadius`(XZ 반지름) · `focusHalfHeight` 로 원기둥을 감싸도록 계산한다.
물체가 전부 지면에 놓이므로 구가 아니라 원기둥이 맞다 — 버스처럼 길고 낮은 것을 구로 감싸면 위아래 여백만 커진다.
세로 화면(aspect < 1)은 가로 화각이 좁아 자동으로 더 물러난다.
**씬에 큰 물체를 넣거나 배치를 넓히면 이 두 값을 같이 고친다.**

`T` 로 그 궤도의 한 시점을 고정한다:

```bash
make snapshot T=2.4 OUT=out/angle.png
```

**특정 오브젝트를 검수할 때는 `EYE`/`LOOK` 으로 카메라를 직접 놓는다** (`Renderer.cameraOverride`).
궤도 카메라는 원점만 보므로 구석에 놓인 물체를 제대로 볼 수 없다:

```bash
make snapshot EYE=-5.0,0.4,-0.2 LOOK=-0.5,-1.4,-4.2 OUT=out/bus.png
```

정확히 수직으로 내려다보면(`forward` 가 ±y) 카메라 기저가 무너지므로 조금 비스듬히 둔다.
확대해서 보려면 `sips --cropOffset <top> <left> -c <h> <w>` 로 잘라내고 `sips -Z` 로 키운다.

바꾼 뒤에는 `make snapshot` → `out/frame.png` 를 Read 로 열어 확인한다.
