# 매끄러운 곡면 다루기

이 렌더러는 **해석적 CSG** 라 메시처럼 노멀을 보간해서 뭉갤 수가 없다. 눈에 보이는 매끈함은
전부 **실제 표면이 그렇게 생겼는지**로 결정된다. 그래서 "둥글게 만들었는데 부자연스럽다" 는
거의 항상 형상 문제이지 셰이딩 문제가 아니다.

## 진단: 어디를 봐야 하는가

곡면이 부자연스러울 때 **하이라이트가 끊기는 선**을 찾는다. 그 선이 곧 법선 불연속이다.

| 증상 | 원인 |
|---|---|
| 꼭짓점에서 **대각선 능선**이 뻗어 나온다 | 아래 "가짜 라운드" — 윤곽 교차로 만든 모서리 |
| 면과 면 사이가 각지다 | 라운드가 아예 없다 |
| 둥근 면 위로 **직선 경계**가 지나간다 | 다른 부품이 겹쳐 있고 바깥면이 거의 같은 평면 |
| 반짝이는 점 얼룩 | 겹친 두 면이 **정확히** 같은 평면 (스티칭) 또는 노이즈 에일리어싱 |

검증 씬이 있다: `CSGScene(.roundBoxTest)` — 왼쪽이 가짜 라운드, 가운데가 진짜, 오른쪽이 차집합.
`Renderer.init` 의 `CSGScene(...)` 을 바꿔서 렌더하면 차이가 한눈에 보인다.

## 가짜 라운드 — 윤곽 교차가 왜 안 되는가

세 방향의 둥근 사각형을 교차시키면(평면도 ∩ 옆모습 ∩ 단면) **모서리(edge)는** 원기둥으로 제대로
둥글어진다. 그런데 **세 면이 만나는 꼭짓점(corner)** 은 원기둥 두 개의 교선(Steinmetz 곡선)이라
구면이 아니고, 거기서 법선이 꺾인다. 실제로 꼭짓점마다 대각선 능선이 남는다.

진짜 둥근 상자는 **민코프스키 합** `상자 ⊕ 반지름 r 구` = `{p : dist(p, 안쪽상자) ≤ r}` 이고,
면은 평평 · 모서리는 원기둥 · **꼭짓점은 구면**이라 법선이 어디서나 연속이다.

## 도구 고르기

| 원하는 것 | 쓸 것 | 부품 수 |
|---|---|---|
| 모든 모서리가 둥근 덩어리 | **`CSG.roundBox(half:radius:)`** | **1** |
| 수직 모서리만 (기둥·띠) | `CSG.roundedRectPrism` | 1 |
| 얇은 판의 앞면 모서리 (창 구멍·램프·표지판) | `CSG.roundedPanel` | 1 |
| 단면만 (터널·레일) | `CSG.roundedSection` | 1 |
| 반지름이 축마다 달라야 함 | 위를 교차 — 단, **꼭짓점 능선을 감수**한다 | 2~3 |
| 아주 복잡한 필렛 | `roundedBox`(27부품) 는 최후의 수단 | 27 |

**덩어리에는 무조건 `roundBox` 를 먼저 쓴다.** 윤곽 교차는 "한 방향만 둥글리고 싶을 때" 쓰는 것이지
전방위 라운드를 흉내 내는 용도가 아니다.

### 한쪽만 둥글리기

`roundBox` 는 반지름이 하나뿐이다. 지붕은 크게 둥글고 바닥은 평평하게 하려면
**형상을 아래로 키워 달고 상자로 잘라낸다** (`Bus.body` 의 `bodyDrop`):

```swift
CSG.roundBox(half: [L, halfH + drop, W], radius: r, .translate(0, centerY - drop, 0), material: m)
  & CSG.box(...)                       // 아래를 평평하게
```
잘린 면 근처만 라운드가 살짝 남고 나머지는 평평해진다.

## `roundBox` 구현 메모 (`Shaders.metal`)

- **볼록**이므로 구간은 하나 → `partIntervals` 의 `convex = true` 경로를 그대로 탄다
- 형상이 **중심대칭**이라 탈출 t 는 방향을 뒤집어 다시 풀면 된다: `ray(o,-d)` 의 진입 `s` → 탈출 `= -s`
- 진입 풀이는 Inigo Quilez, ["Intersectors"](https://iquilezles.org/articles/intersectors/) 의
  `roundedboxIntersect` 를 따랐고 **양수 t 필터만 제거**했다 —
  CSG 는 원점이 안에 있는(t 가 음수인) 레이도 다뤄야 한다
- 법선은 닫힌 식 하나로 끝난다: `normalize(p - clamp(p, -b, b))`.
  면·모서리·꼭짓점을 **구분하지 않으므로 이음매가 없다.** 이게 매끈함의 핵심이다
- 크기를 변환 행렬이 아니라 `data` 로 받는다. **비균등 스케일하면 꼭짓점이 타원체가 되어**
  매끈함이 깨지기 때문. `CSG.bounds()` 도 `data` 에서 AABB 를 읽는 특례가 있다

## 새 매끄러운 부품을 추가할 때

`csg-part` 스킬의 절차를 따르되, 매끈함을 위해 두 가지를 더 지킨다:

1. **법선을 케이스별로 나누지 않는다.** 면/모서리/꼭짓점마다 다른 식을 쓰면 경계에서 어긋난다.
   가능하면 SDF 의 그래디언트처럼 **하나의 닫힌 식**으로 뽑는다
   (민코프스키 합 계열은 대부분 `p - (가장 가까운 안쪽 점)` 으로 떨어진다)
2. **볼록이면 진입/탈출 두 개만** `addCand` 한다. 조각별로 후보를 다 넣으면 `MAX_CANDS`(6)를 넘긴다

## ⚠︎ 둥근 껍데기 안에 각진 상자를 넣지 마라

**이 저장소에서 같은 버그가 세 번 났다.** 둥근 상자로 만든 껍데기는 코너·모서리에서
안으로 말려 들어가는데, 안에 넣는 각진 상자는 "평평한 부분 기준" 치수라 **말려 들어간 만큼 뚫고 나온다.**

| 언제 | 증상 |
|---|---|
| 실내를 파내는 상자가 지붕보다 높음 | 지붕 양쪽에 **슬롯**이 뚫린다 (위에서만 보임) |
| 실내를 파내는 상자가 코너보다 넓음 | 뒤 코너에 **관통 구멍**이 뚫린다 |
| 실내 물체(엔진실 등)가 코너보다 넓음 | 검은 판이 **차체 밖에 서 있는 것처럼** 보인다 |

**해법 둘**

1. **파내는 것도 같은 모양으로.** 둥근 상자를 두께 t 만큼 줄이면 **또 하나의 둥근 상자**다
   (안쪽 상자는 그대로, 반지름만 `r - t`). 벽 두께가 어디서나 정확히 t 가 된다:
   ```swift
   CSG.roundBox(half: bodyHalf - .init(repeating: t), radius: bodyCorner - t, ...)
   ```
2. **넣는 물체는 그 지점의 실제 반폭에서 역산한다.** 고정 좌표로 두면 코너 반지름을 바꾸는 순간 터진다.
   `Bus.cabinHalfWidth(atX:y:)` / `Bus.halfWidth(atX:)` / `Bus.roofTop(atX:z:)` 가 그런 헬퍼다.

### 눈으로 찾지 말고 검사로 잡는다

이 버그는 **각도를 안 보면 안 보인다.** 그래서 자동 검사를 붙여 뒀고, `CSGScene` 이 만들어질 때마다
돌면서 콘솔에 `⚠️ Bus: ...` 로 찍는다:

| 검사 | 잡는 것 |
|---|---|
| `Bus.interiorViolations` | 실내 부품이 둥근 차체를 **뚫고 나감** (AABB 꼭짓점 8개를 실내 형상과 대조) |
| `Bus.floatingViolations` | 표면 부품이 차체에서 **떨어져 뜸** |

부유 검사는 **연결성**으로 판정한다 — 차체에 닿았거나, 이미 붙은 다른 부품과 AABB 가 겹치면 붙은 것.
사이드미러처럼 팔에 매달린 구조(차체 ← 팔 ← 기둥 ← 거울)를 오탐하지 않으려면 이래야 한다.
실제로 코너 반지름을 0.36 → 0.45 로 키웠을 때 **미러 팔이 17 cm 떠 있는 것**을 이 검사가 잡았다.

검사에 쓰는 도구:
- `CSG.partBounds()` — 조립체 안의 **부품마다** AABB 를 하나씩 준다
- `Bus.isInsideBody(_:margin:)` / `isInsideCabin(_:margin:)` — 둥근 상자 SDF 판정

**AABB 가 정확해야 검사가 쓸모 있다.** `polygon` 계열은 `data[0]` 에 실제 국소 크기를 실어
AABB 를 조인다 — 안 그러면 얇은 판이 정육면체만 한 상자를 갖게 되어 오탐이 쏟아지고,
가속 구조에서도 쓸데없는 레이가 들어온다.

수동 확인이 필요하면 오브젝트를 하나씩만 배치해 렌더한다 (`placements += (1...N)` 의 N 을 줄여 가며).
**위·아래·뒤에서도 반드시 본다** — 정면에서는 안 보인다.

## 유기적 형상 (인체 · 동물) — `CSG.blob`

불리언으로는 **안 된다.** 타원체를 아무리 잘 배치해도 합칠 때마다 교선에 능선이 남고,
그 능선을 피하려다 보면 근육 굴곡을 포기하게 된다. 이 문제를 모델 쪽에서 풀 수 없어서
**엔진에 부품을 하나 추가했다**: `CSG_PART_BLOB` — 타원체·둥근 원뿔의 거리장을 smooth-min 으로
섞고 구 추적으로 표면을 찾는다. 이어 붙는 자리가 애초에 생기지 않는다. `RayTracer/Figure.swift` 가 표준.

```swift
CSG.blob([
    .ell([x, y, z], [rx, ry, rz], blend: 0.5),                       // 타원체
    .ell(c, r, blend: 0.08, negative: true, tilt: ([0,0,1], 7)),      // 기울인 음각 — 눈꼬리 올린 눈확
    .cone(a, b, ra, rb, blend: 0.04),                                 // 둥근 원뿔 — 팔다리 마디
    .curve(a, via: ctrl, b, ra, rb, blend: 0.03),                     // 2차 베지에 튜브 — 눈썹·콧날·머리 타래·안경 다리
], inflate: 0, material: skin)
```

원소 종류는 셋이고 **굽은 것은 전부 `curve`** 다. 곧은 원뿔을 세 마디 이어 붙이면 마디마다 꺾인 각이
남는다 (헤어라인이 그랬다). 콧날도 원뿔로 두면 얼굴에서 능선처럼 튀어나와 짙은 그림자를 만든다 —
베지에로 미간에서는 표면 안에 있다가 코끝으로 갈수록 드러나게 한다. `tilt` 는 타원체 전용이다
(원뿔·베지에는 끝점이 방향을 정한다). 베지에는 3차 방정식을 풀어 타원체보다 몇 배 비싸니 얼굴에 몇 개만.

| 규칙 | 왜 |
|---|---|
| **팔다리는 `cone`** | 구를 줄줄이 꿰면 간격이 반지름의 1.5배만 넘어도 메타볼 사슬이 소시지처럼 울퉁불퉁하다 |
| 원뿔끼리는 끝점·반지름을 공유하고 **blend 는 0.04 정도** | 이미 이어져 있으니 기울기만 둥글리면 된다. 크게 주면 smin 이 관절마다 k/4 만큼 살을 더해 윤곽이 물결친다 |
| 몸통 덩어리는 blend 0.6~0.9, 코끝은 0.05~0.1 | blend = 그 원소가 이웃과 섞이는 반경. 작을수록 또렷하게 남는다 |
| **원소 순서 = 조각 순서** | 두개골 → 턱 → 눈확(음각) → 눈꺼풀 → 코. 눈꺼풀을 음각보다 먼저 넣으면 통째로 파여 사라진다 |
| 음의 원소는 **아주 작게** 시작 | 쇄골 오목을 0.5 크기로 팠더니 어깨에 구덩이가 두 개 생겼다. 0.26×0.07 이 맞았다 |
| 오브젝트는 몸통(+머리) · 팔 각각 · 다리 각각 | 한 덩어리로 두면 팔·몸·팔을 지나는 레이가 구간 3개 = `MAX_CANDS`(6) 를 꽉 채운다. 이음매는 옷(수영복)이 덮는 골반과, 어깨의 삼각근 경계에 둔다 |
| 얼굴 부속은 **표면 방정식이 아니라 blob 원소**로 | 눈꺼풀·코·입 주변을 같은 덩어리 안에 넣으면 알아서 섞인다. 색이 다른 것(입술·안구)만 별도 오브젝트 |

**옷은 `inflate` 로 만든다.** 같은 원소 목록에 `inflate: 0.055` 를 주면 SDF 에서 상수를 빼는
것이라 **정확한 오프셋 표면**이 된다. 그리고 **반드시 원래 몸을 빼서 껍데기로**:
`blob(e, inflate: t) - blob(e)` 를 마스크로 자른다. 빼지 않으면 `덩어리 ∩ 마스크` 가 통짜 슬래브라
위에서 볼 때 몸통 단면만 한 평평한 선반이 드러난다. 원소를 일부만 골라 쓰지도 말 것 —
빠뜨린 원소(목·승모근)가 만든 살이 옷을 뚫고 나온다.

**셰이더 쪽에서 겪은 것** (`candBlob`)
- 순수 구 추적은 실루엣을 스치는 레이가 거리장이 작은 채로 기어가다 스텝을 다 쓰고
  **그냥 빗나간다** → 팔다리 가장자리가 물어뜯긴 듯 우글거린다
- 최소 스텝을 키우면 표면을 뛰어넘어 **안쪽에 착지**하고 거기서 교차를 기록해 형상이 부풀고 시커멓게 된다
- 답은 둘을 분리하는 것: **전진은 구간 길이에 비례한 최소 스텝으로 보장하고, 정확도는 부호가
  바뀐 구간의 이분법이 책임진다.** 스텝은 이제 "얇은 것을 통째로 건너뛰는가"만 결정한다
- 표면 위치가 수치적이라 그림자 레이 오프셋을 0.003 → 0.014 로 올렸다

**피부 셰이딩 (`Material.sss`)**
- 형상이 좋아도 명암 경계가 칼같으면 석고상이다. `sss` 는 감싸는 확산 + 터미네이터의 붉은 띠로 이걸 흉내낸다
- 0.45~0.55 가 맞다. 0.85 로 두면 빛이 뒤까지 감싸 **입체감이 통째로 날아간다**
- 감싸는 확산은 n·l < 0 인 곳까지 빛을 끌고 가는데, 거기서 그림자 레이는 반드시 자기 자신을 맞아 0 을 준다 →
  부드러운 경계가 다시 칼같이 잘린다. 그래서 `sss` 재질은 빛을 향할수록만 그림자를 신뢰한다
- `grain` 은 쓰지 않는다. 노이즈가 `h.pos.xz` 기준이라 수직면(얼굴)에서는 커다란 회색 반점이 된다
- `gloss` 는 0.15 언저리, 하이라이트도 sss 재질에서는 넓고 약하게 줄여 놨다

**등신 비율**: 키 ÷ 머리 길이 = 7.2~7.5. 6 이면 그 자리에서 인형이다.

**얼굴** — 비율은 `Figure.headC` 기준으로 잰다: 눈 = 정수리~턱의 정확히 중간, 코끝 = 눈~턱의 중간,
입 = 코~턱의 위쪽 1/3. 여성 얼굴은 눈두덩 융기 없음 · 작은 턱 · 얕은 눈확 · 높은 광대.
눈은 공막 + 윤부(어두운 테) + 홍채 + 동공 + **유리 각막** — 각막이 만드는 캐치라이트가 눈을 살린다.
속눈썹(윗눈꺼풀 가장자리의 검은 선 하나)과 눈썹은 별도 오브젝트로 표면 **밖에** 둔다 (0.05 안쪽이면 사라진다).
콧구멍은 파지 않는다 — 이 해상도에서는 어디에 파도 코 밑 얼룩이다.

**머리카락** — 가닥을 기하로 심지 마라. 엔진 블레이드처럼 인스턴싱해 봤지만(두 겹 180가닥)
어떻게 해도 튜브 다발로 읽힌다. 눈은 굵은 튜브를 개별 물체로 본다.
답은 **매끈한 덩어리 + `MATERIAL_HAIR`**: 가닥 방향(표면을 따라 아래)으로 흐르는 미세 법선 결 +
Kajiya-Kay 비등방 하이라이트 두 로브. 이마 위에 앞머리 덩어리를 따로 얹으면 챙이 되니
두상 원소를 앞으로 늘려 헤어라인을 잡는다.

**조명** — 인물은 조명이 곧 인상이다. `CSGScene.sunDirection` 으로 카메라 쪽 위에서 비추고
(`(0.45, 0.8, 0.85)`), 피부에는 카메라 방향 필 라이트가 들어간다. 머리 위 태양은 누구든 해골로 만든다.

**실사는 포기하고 양식화했다.** 사람 얼굴은 뇌에 전용 회로가 있어 mm 단위 오차가 즉시 "이상하다"로 읽히고
(불쾌한 골짜기), 텍스처 없는 이 렌더러로는 그 골짜기를 못 건넌다. 양식화(6.5 등신, 큰 눈, 단추 코,
작은 입, 통통한 볼, 타래 단위 머리카락)는 골짜기를 **우회**하므로 같은 도구로 볼만한 결과가 나온다.
- 홍채·동공은 안구 앞면(반지름)에 **살짝 튀어나오게** — 안쪽이면 공막이 덮어 회색 원판이 된다
- 양식화 눈에 유리 각막을 얹지 마라 — 하늘을 통째로 비춰 유리구슬이 된다. 캐치라이트는 흰 점 하나로 그린다
- 입선 양 끝을 1 mm 올린 두 마디 원뿔이 무표정과 미소를 가른다
- 머리카락은 가닥이 아니라 **타래**: 굵은 원뿔 몇 개 + 이마를 가로지르는 앞머리 한 타래. 얼굴을 파낸 **뒤에** 앞머리를 접는다

**사진을 참고할 때 잰 것** — 이마 : 코 : 턱 = 1 : 1 : 1 (헤어라인·눈썹·코끝·턱끝), 얼굴 폭/길이 ≈ 0.78,
눈썹은 눈 중심에서 0.18 위, 눈은 실제 크기. 처음엔 눈이 만화처럼 크고 눈썹이 높고 이마가 얼굴의 절반이었다.
**안경**: 림 = `cylinder − cylinder` 를 `rotateX(90)` 으로 눕힌 납작 고리, 다리·브릿지 = 베지에 튜브,
렌즈 = 얇은 유리 원기둥 (별도 오브젝트). `Figure.glassesFrame` / `glassesLenses`.

**사진과 비교하며 고친 순서 (효과 큰 것부터)**: ① 눈 사이 간격 = 눈 하나 폭 (0.7 이면 몰린 눈)
② 태양을 더 정면으로 (`(0.38, 0.58, 1.05)`) — 코 밑 그늘이 사라진다 ③ 헤어라인 내리고 정수리 볼륨 줄이기
④ 윗입술은 **베지에 두 줄**(입꼬리→산→결절)로 큐피드 활, 아랫입술은 타원체 ⑤ 얼굴 파내기 blend 0.24 — 헤어라인이 부드러워진다
⑥ 볼 살은 **작게** — 크게 두면 다람쥐 볼이 되고 입까지 파묻힌다 ⑦ 한쪽 머리는 귀 뒤로 넘겨 귀걸이가 보이게.
쌍꺼풀선은 얕은 음각 베지에(r 0.012)를 눈꺼풀 **다음에** 접는다 — 효과는 미미하다.

**검수는 2배 렌더 후 축소** (scratchpad `ss.sh`). 1 spp 렌더의 계단 때문에 속눈썹·손가락 판단이 안 된다.
그리고 **스크립트가 크래시를 삼키지 않는지 확인할 것** — 원소 40개 한계 precondition 에 걸려 죽었는데
옛 PNG 를 보며 "왜 안 바뀌지" 한 적이 있다.

## 매끈한 형상을 망치는 흔한 실수

- **겹친 부품의 바깥면을 같은 평면에 둔다** → 픽셀마다 이기는 쪽이 갈려 흑백 얼룩.
  앞뒤로 최소 2~3 cm 어긋나게 둔다
- **차집합으로 곡면을 자른다** → 잘린 자리는 반드시 날카롭다. 자를 거면 자르는 쪽도 곡면으로
- **큰 면을 완전한 평면으로 둔다** → 라운드가 아무리 좋아도 가운데가 죽는다.
  `Bus` 는 반경 22 m 원기둥으로 옆면을 4 cm 볼록하게 만든다
- **고광택(`gloss` ≥ 0.9) 평면** → 스페큘러가 픽셀보다 좁아져 반짝임. 0.7 언저리로 낮춘다
